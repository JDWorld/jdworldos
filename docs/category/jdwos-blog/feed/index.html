JÐWØ®LÐ ØS (Based on Arch Linux KDE)

Questa è la storia di come ho piallato il sistema (Arch Linux), bandito l’AUR e creato il formato nativo .jdw per il progetto JDWorld OS (basato su Arch Linux).

Capitolo 1: JÐWØ®LÐ ØS System Tray Menù

Il cuore dell’interfaccia utente di JDWorld OS (che gia utilizzavo in quanto avevo creato il pacchetto per aur poi convertito in .jdw) è gestito da un menù avanzato, multilivello e dinamico, sviluppato in Python 3 utilizzando le librerie grafiche native PyQt6 (QWidgets).

A differenza dei menù tradizionali che richiedono un riavvio o una ricompilazione del codice per essere aggiornati, questo modulo è stato progettato con una logica Hot-Reload (aggiornamento in tempo reale) basata su semplici file di testo (.txt).

Tutto è nato da qui: dal voler un menù nel vassoio di sistema (ispirato a come gestisco Windows tramite software open-source e PortableApps) dove poter inserire a mio piacimento i collegamenti delle applicazioni che uso di più.

Il JDWorld System Tray Menù si è poi evoluto in un intero sistema operativo, completo di Gestore di Pacchetti e formato proprietario dedicato .jdw. Senza di esso non ci sarebbe stato alcun JDWorld OS, nessun Package Manager e nessun formato nativo. All’inizio il sistema leggeva da un unico file di testo grezzo contenente categorie e voci. Era elementare ma funzionale: faceva il suo dovere ed evitava di farmi scrivere comandi chilometrici nel terminale. Poi, studiando e smanettando, si è evoluto in quello che è adesso.

Capitolo 2: L’Apocalisse dell’AUR e la Reazione della Ragione

Dopo l’attacco alla supply chain che ha colpito l’AUR tra il 12 e il 16 giugno 2026, ho preso l’unica decisione sensata, logica e responsabile: fare tabula rasa. Ho piallato ogni computer della rete, cambiato ogni singola password e ridotto l’architettura all’osso.

Il Formato Nativo .jdw

Invece di piangere sulle ceneri di makepkg, ho dato vita a un’architettura di packaging proprietaria e modulare. Ogni estensione del mio menù in PyQt6, o pacchetto dedicato al progetto, viene compresso in un file .jdw che include:

  1. jdw-package.info – La scheda tecnica dei metadati in stile Arch Web.
  2. install.sh – Gestione lineare dell’installazione (permessi e copia dei file).
  3. remove.sh – Rimozione atomica senza lasciare residui nel sistema.

Capitolo 3: La Rinascita Atomica

Avevo un sogno: Crearmi un OS personalizzato basato su Arch Linux, ma poi è accaduto l’olocausto dell’AUR, proprio mentre stavo imparando a creare pacchetti con makepkg da caricare sui repository della community, la cronaca nera ha cambiato totalmente la mia rotta!

Così, con l’aiuto di Google AI, ho reinventato un gestore di pacchetti con formato proprietario .jdw dedicato a JDWorld OS e bandito AUR. Il mio nuovo Package Manager può essere integrato in qualsiasi distribuzione Arch Linux (preferibilmente con ambiente desktop KDE).

Se vuoi provare JDWorld OS così come l’ho concepito (qui la guida completa), non serve scaricare una ISO personalizzata per lanciarla in live o installarla. Ti basta installare Arch Linux pulito con il gruppo plasma-meta (la via di mezzo perfetta tra l’installazione minimale e quella full di KDE), adottare il JDWorld OS Package Manager e installare la mia configurazione nativa (sfondi horror, effetti audio, schemi colore, icone, menù dedicati e tanto altro ancora).

Se proprio vuoi strafare e avere la mia esatta base di partenza (il procedimento completo è nella mia testa), puoi slegare i pacchetti dal plasma-meta ed eliminare il bloatware. Via Discover, Flatpak, Oxygen ed Air: in JDWorld OS il software spazzatura è totalmente assente.

Lo Stato Attuale del Sistema

  • 0 pacchetti AUR (Vade Retro!)

Il JDWorld OS Packages Manages è il Nuovo Gestore e Generatore di Pacchetti per JDWorld OS.

Dopo l’olocausto abbattutosi su AUR (avvenuto tra il 12 ed il 16 giugno 2026), ho abbandonato l’idea di creare pacchetti per arch (.pkg.tar.zst) dedicati al mio progetto (basato su arch) e, con l’aiuto di Google AI ho creato un formato proprietario per il JDWorld OS (chiamandolo .jdw) e contiene:

  1. I file e le cartelle da copiare nel sistema e/o nella cartella utente.
  2. install.sh gestisce i permessi e la copia.
  3. remove.sh gestisce la rimozione chirugica del pacchetto installato
  4. Licenza BSD 2 Clausule
  5. jdw-package.info, necessario per visualizzare le informazioni sul pacchetto tramite il comando jdw-info nome-pacchetto (aggiunto il 26-06-2026)

Questo script automatizza la creazione del pacchetto. Sostituisce il vecchio flusso che creava il PKGBUILD (del vecchio generatore di pacchetti). Prende la cartella del progetto e la trasforma in un unico file compresso (nome-pacchetto.jdw).

Come si presenta la cartella del nuovo generatore di pacchetti (JDWOS-PM):

  • jdw-build è lo script che crea il pacchetto partendo dalla cartella del progetto.
    Comando: jdw-build nome-cartella (privato, non rilasciato al pubblico)
  • jdw-install è lo script che installa il pacchetto.
    Comando: sudo jdw-install nome-pacchetto (se installi da cloud) e/o sudo jdw-install nome-pacchetto.jdw (se hai scaricato il pacchetto .JDW e preferisci un’installazione da file)
  • jdw-remove è lo script che si occupa di rimuovere il pacchetto installato.
    Comando: sudo jdw-remove nome-pacchetto (es: jdwos-stm)
  • jdw-list è lo script che mostra la lista dei pacchetti JDW a bordo. (aggiungo il 25-06-2026)
    Comando: jdw-list
  • jdw-info è lo script che mostra le informazioni sul pacchetto scelto. (aggiunto il 26-06-2026)
    Comando: jdw-info nome-pacchetto
  • jdw-help è lo script che mostra il menù dei comandi del JDWorld OS (aggiunto il 13-07-2026)
    Comando: jdw-help

Perché la creazione di un Gestore di Pacchetti dedicato è geniale per il mio scenario attuale?

  • Sicurezza Totale: Il codice lo scrivo io, i file li sposto io. Nessun malware AUR, nessuna dipendenza npm, nessun server web impazzito.
  • Dipendenze Ufficiali: Le scarica direttamente dai Repository Ufficiali di Arch Linux e/o dai Repository Ufficiali della Distro basata su Arch Linux

]]> https://jdworld.github.io/jdworldos/jdwos-blog/mr_jack/26/feed/ 0 JÐWØ®LÐ ØS System Tray Menù [PyQT6] https://jdworld.github.io/jdworldos/jdwos-blog/mr_jack/22/ https://jdworld.github.io/jdworldos/jdwos-blog/mr_jack/22/#respond Mon, 27 Apr 2026 00:42:00 +0000 https://jdworld-os.netbird.cloud/?p=22

Il cuore dell’interfaccia utente del mio Arch Linux (KDE Plasma) è gestito da un menù avanzato, multilivello e dinamico sviluppato in Python 3 utilizzando le librerie grafiche native PyQt6 (QWidgets).

A differenza dei menù tradizionali che richiedono un riavvio o una ricompilazione per essere aggiornati, questo modulo è stato progettato con una logica Hot-Reload (aggiornamento in tempo reale) basata su semplici file di testo (.txt).

1. Architettura e Percorsi di Sistema

Il menù risiede stabilmente in cartelle dedicate per garantire isolamento e sicurezza:

  • Eseguibile principale: /usr/bin/jdw_menu (o script di avvio richiamabile da tastiera/pannello).
  • Risorse di sistema: /usr/share/jdw-stm/ (contiene i file core e le icone).

2. Logica Dinamica “Multilivello” (Il segreto della velocità)

Il menù non ha un database pesante; legge direttamente i file di configurazione scritti in formato testo (.txt). All’avvio, il programma esegue una fusione in tempo reale (Merge) di due sorgenti distinte:

  1. Livello di Sistema (/usr/share/jdw-stm/menu.d/): Contiene i comandi globali predefiniti del sistema operativo, validi per tutti gli utenti.
  2. Livello Utente (~/.local/share/jdw-stm/menu.d/): Contiene le personalizzazioni, gli script locali e i comandi aggiunti dall’utente nella propria Home.

Come funziona il Merge:
Se un file con lo stesso nome esiste in entrambe le cartelle, il codice PyQt6 li unisce dinamicamente, mostrando all’utente un’unica lista ordinata. Questo permette di aggiornare il sistema via pacchetto pacman senza mai rischiare di cancellare i comandi personali creati dall’utente.

3. Struttura dei File dei Comandi (.txt)

I file all’interno della cartella menu.d/ sono semplicissimi da modificare. Ogni riga rappresenta un comando nel menù strutturato in questo modo:

Nome Pulsante|Comando da Eseguire|Icona

Esempio pratico:

Se nel file multimedia.txt inseriamo:

  • Scarica Video|yt-dlp -f mp4 %s|video-player.png
  • Converti in MP3|ffmpeg -i %s -vn %s.mp3|audio-headset.svg

Il menù in PyQt6 farà tre cose in automatico:

  1. Disegnerà un pulsante grafico con la scritta “Scarica Video”.
  2. Assocerà l’icona cercandola in /usr/share/pixmaps/.
  3. Eseguirà il comando Bash in background (o in una finestra di Konsole) al click dell’utente.

4. Vantaggi di questo approccio

  • Leggerezza Assoluta: Ideale sia per i PC corazzati ultra moderni, sia per i PC vintage con vecchi HDD e poca RAM.
  • Zero Configurazioni Grafiche a Mano: L’interfaccia si auto-costruisce da sola in base a quello che trova scritto nei file di testo.

Regola d’oro per le Categorie del Menù

Il nome del file .txt definisce automaticamente il nome della scheda o della categoria all’interno del menù in PyQt6.

  • Esempio: Un file chiamato 01_Sviluppo.txt creerà una sezione chiamata Sviluppo posizionata in cima al menù.
  • I file inseriti nella cartella utente (~/.local/share/jdwos-stm/menu.d/) che hanno lo stesso nome di quelli di sistema verranno fusi, aggiungendo i tasti personali in fondo a quella specifica categoria.
